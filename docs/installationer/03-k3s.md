# 3 K3s

K3s installeras som ett kluster med en nod, med Traefik och ServiceLB som följer med. Kubernetes-API:t (port 6443) ska bara nås via NetBird, och sajten publiceras via Traefik och Gateway API enligt uppgiftens guide.  

## K3S-1 — Brandväggsregler för K3s

**Status:** Åtgärdad · Datum: 2026-10-01  

**Åtgärd:** Lade till två UFW-regler före installationen: 6443/tcp på gränssnittet wt0 (IPv4 och IPv6) så att Kubernetes-API:t bara nås via NetBird, och all trafik på gränssnittet cni0 från podd-nätet 10.42.0.0/16 så att poddarna kan prata med varandra. API-porten är inte öppen mot internet.  

**Verifiering:** `ufw status numbered` → regel 2 och 5: 6443/tcp on wt0 (IPv4 och IPv6), regel 3: Anywhere on cni0 från 10.42.0.0/16.  

## K3S-2 — K3s installerat med Traefik och ServiceLB

**Status:** Åtgärdad · Datum: 2026-10-01  

**Åtgärd:** Hämtade installationsskriptet från get.k3s.io och körde det med INSTALL_K3S_EXEC="server --tls-san <netbird-ip>". Standardinstallationen valdes (Traefik och ServiceLB ingår). Flaggan --tls-san gör att API-certifikatet godkänner NetBird-adressen, så att kubectl fungerar över NetBird.  

**Verifiering:** `systemctl is-active k3s` → active. k3s kubectl get nodes → its1 Ready, control-plane, v1.36.4+k3s1. k3s kubectl get pods -A → coredns, local-path-provisioner, metrics-server, traefik och svclb-traefik Running, helm-install-traefik och helm-install-traefik-crd Completed. API-certifikatets subjectAltName innehåller <netbird-ip>.  

## K3S-3 — kubectl från administratörens dator över NetBird

**Status:** Åtgärdad · Datum: 2026-10-01  

**Åtgärd:** Kopierade K3s kubeconfig (/etc/rancher/k3s/k3s.yaml) till administratörens Windows-dator, tog bort den tillfälliga kopian på servern och ändrade server-adressen från 127.0.0.1 till NetBird-adressen <netbird-ip>. Kubernetes-API:t nås därmed bara via NetBird. Filen är en admin-nyckel till klustret och delas inte eller läggs i git.  

**Verifiering:** `kubectl get nodes` → its1 Ready, control-plane, v1.36.4+k3s1.  

## K3S-4 — Sajten publicerad via Traefik och Gateway API

**Status:** Åtgärdad · Datum: 2026-10-01  

**Åtgärd:** Följde uppgiftens guide (repo aspcodenet/clusterDemo250919-main). Applicerade 02-traefik-gateway-config.yaml (Gateway API-provider i Traefik), 01-namespace.yaml (yatest), 40-site.yaml (Deployment med 3 repliker av imagen yeasy/simple-web och en ClusterIP-tjänst) och 50-gateway.yaml (HTTPRoute). Två ändringar mot manifesten: hostnamnet i HTTPRoute sattes till its1.example.com, och containerPort och targetPort ändrades från 8787 till 80, eftersom imagen lyssnar på port 80 (med 8787 svarade Traefik 502 Bad Gateway). Routen är kopplad till HTTP-listenern (web), och HTTPS på port 443 återstår.  

**Verifiering:** `kubectl get gatewayclass traefik` → ACCEPTED True. kubectl get gateway -A → traefik-gateway PROGRAMMED True. kubectl get pods -n yatest → 3 poddar Running (1/1). kubectl describe httproute sites → Accepted och ResolvedRefs. curl -i -H "Host: its1.example.com" http://<netbird-ip>/ från servern → HTTP/1.1 200 OK, sidan visar förfrågan från Traefik-podden till webbservern 10.42.0.15. kubectl port-forward mot Traefik från administratörens dator, följt av curl -H "Host: its1.example.com" http://localhost:8080/ → HTTP/1.1 200 OK, den här gången från webbservern 10.42.0.14, vilket visar att förfrågningarna fördelas mellan replikerna.  

## K3S-5 — HTTPS-listener med självsignerat certifikat för Cloudflare

**Status:** Åtgärdad · Datum: 2026-10-01  

**Åtgärd:** Cloudflare ansluter till servern på port 443, men guidens Gateway har bara en HTTP-listener (port 80), som Cloudflare-filtret stänger utifrån (CF-4). Skapade därför ett självsignerat certifikat för its1.example.com med openssl och lade det som en TLS-secret, its1-tls, i namnrymden kube-system (där Gateway:n ligger). Utökade 02-traefik-gateway-config.yaml med en HTTPS-listener, websecure (port 8443 internt, som K3s ServiceLB exponerar som 443), med namespacePolicy from: All och certificateRefs till its1-tls, och applicerade den. Ändrade i 50-gateway.yaml sectionName i HTTPRoute från web till websecure. Cloudflare-läget Full krävs för att ett självsignerat certifikat ska godtas.  

**Verifiering:** `curl -k -i -H "Host: its1.example.com" https://localhost:8443/ via kubectl port-forward mot Traefik från administratörens dator` → HTTP/1.1 200 OK, sidan visar förfrågan från Traefik-podden till webbservern 10.42.0.14.  

## K3S-6 — Lynis-körning efter K3s

**Status:** Verifierad · Datum: 2026-10-01  

**Åtgärd:** Körde Lynis 3.1.6 (lynis audit system) efter att K3s, Cloudflare-filtret och sajten var på plats, för att jämföra med körningen före K3s. Inga ändringar gjordes med anledning av resultatet.  

**Verifiering:** `grep hardening_index /var/log/lynis-report.dat` → hardening_index=72, samma som före K3s. 266 tester utförda, 1 varning (PKGS-7388: ingen säkerhetsrepo hittades i sources.list eller sources.list.d) och 36 förslag. Bland förslagen finns GRUB-lösenord (BOOT-5122), som är en medveten avvikelse. Varningen kontrollerades: /etc/apt/sources.list.d/ubuntu.sources innehåller Suites: resolute-security från mirror.hetzner.com/ubuntu/security, så säkerhetsförrådet finns och varningen bedöms vara falsk.  

## K3S-7 — Sajten testad över HTTP och HTTPS från administratörens dator

**Status:** Verifierad · Datum: 2026-10-01  

**Åtgärd:** För att följa guiden (HTTP på port 80) och testa både HTTP och HTTPS på sajten över det publika kortet utan Cloudflare lades en tillfällig regel in i tabellen cf_filter som släpper igenom administratörens dator på port 80 och 443 (nft insert rule). Regeln försvinner när filterscriptet körs nästa gång, eftersom tabellen då ersätts. Routen i 50-gateway.yaml kopplades till både HTTP-listenern (web) och HTTPS-listenern (websecure).  

**Verifiering:** `curl -i -m 10 -H "Host: its1.example.com" http://<publik-ip>/ från administratörens dator` → HTTP/1.1 200 OK, webbservern 10.42.0.14. curl -k -i -m 10 -H "Host: its1.example.com" https://<publik-ip>/ → HTTP/1.1 200 OK, webbservern 10.42.0.15 (en annan replik). Trafik som kommer in på det publika kortet eth0 når alltså poddarna, över både port 80 och 443.
